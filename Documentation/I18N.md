# Internationalization

English is the default. English and Simplified Chinese switch immediately on the offline unlock screen and in Settings. A language change does not replace the root view, clear inputs, close an existing sheet, change wallets, restart Tor, requote or send a transaction.

## Resource layout

- [English Localizable.strings](../Sources/WalletCore/Resources/en.lproj/Localizable.strings)
- [Simplified Chinese Localizable.strings](../Sources/WalletCore/Resources/zh-Hans.lproj/Localizable.strings)
- [i18n.json](../Sources/WalletCore/Resources/i18n.json): default language, native language names, compatibility aliases and immutable legacy persisted labels.
- [Localization.swift](../Sources/WalletCore/Models/Localization.swift): resource loading, observable device preference and opaque argument rendering.

The package declares defaultLocalization in [Package.swift](../Package.swift); SwiftPM processes the native localized resources into WalletCore's bundle. [Info.plist](../Configuration/Info.plist) declares the same language identifiers. No translation service or runtime download is used. See Apple's [package-resource localization](https://developer.apple.com/documentation/xcode/localizing-package-resources) and [ObservationRegistrar](https://developer.apple.com/documentation/observation/observationregistrar) documentation.

## Adding a message

Use a stable identifier in Swift and matching entries in both language files. Keep the identifier unchanged when editing wording. Do not use a sentence as a key or embed translated prose in Swift.

~~~swift
L("wallet.lock")
L("message.connecting_to_tor_0", progress)
~~~

Numbered placeholders in the resources correspond to positional arguments. They may be reordered, but each must occur exactly once. Values are appended without interpreting them as format strings or new placeholders. Addresses, amounts, hashes, protocol identifiers and user names remain opaque data.

LK resolves application-owned catalog labels and compatibility aliases. LS is display-only compatibility for recognized app-generated cached descriptions in either language. Never use either helper to interpret transaction state, alter a user name or rewrite a signing payload. Unrecognized historical/node messages retain their original text.

Legacy transaction labels remain in i18n.json solely for old stored-record decoding and APIs. They are independent of the current UI language; changing their values would require a separate persistence migration. Account-profile labels store resource identifiers instead of an initialization-time translated string.

## Live updates and validation

WalletLanguagePreferences registers reads with ObservationRegistrar and publishes main-actor mutations. SwiftUI reads through L/LK/LS therefore update when the selected language changes. The selection is persisted in app-local UserDefaults, without synchronization or a dependency on Apple's process-wide language cache. Inputs and view identities are retained.

~~~bash
python3 -m unittest discover -s Tests/Localization -p 'test_*.py'
python3 Tools/Localization/catalog.py --check
./Scripts/swift.sh test
.build/out/Products/Debug/VeilWallet --verify-i18n .build/native-language-switch.json
~~~

The checker rejects missing keys, unequal language catalogs, invalid argument counts and translated Swift literals. Unit tests cover live observation, persistence, aliases, legacy states, resource encoding and opaque values. The DEBUG native-window check clicks the real Settings language control in both directions, checks actual sidebar/profile label updates and preserves edited form state. It uses an in-memory preference store and public preview model, without reading a real vault, modifying user preferences or starting network connections. Verification hooks do not ship in Release.
