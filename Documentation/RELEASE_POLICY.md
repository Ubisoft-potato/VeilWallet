# Source previews and binary distribution

The release workflow publishes ad-hoc signed development installers with exact corresponding-source deliveries and replacement/relink evidence. It does not require Apple Developer credentials or Apple notarization. Binary upload still fails closed unless the exact committed tree and every required material pass validation.

[BinaryDistribution.json](../Configuration/BinaryDistribution.json) is the reviewed policy. The workflow runs [check-release-policy.py](../Scripts/check-release-policy.py) before upload and uses its enabled output. An unchecked manual-dispatch flag or repository variable cannot bypass it. Invalid policies/materials fail closed.

## Required delivery before binary upload

Provide a reviewed materials manifest for the exact committed source tree. It must record:

- Schema version 1 and sourceTree matching the release HEAD tree.
- BUILD-INFO.json from the exact clean committed tree; dirty or mismatched binaries are rejected.
- reviewedForBinaryDistribution and relinkVerified set to true after actual review/testing.
- The complete component inventory: application, swift-dependencies, go-dependencies, go-runtime, tor, monero, node and privacy-helper.
- A nonempty artifacts list with project-relative path and SHA256 for each corresponding-source/relink delivery. Every file must exist and match its hash; escaping paths and symlinks are rejected.

The materials cover exact source revisions, local modifications, licenses and build/relink instructions for the distributed versions. Repository-only source archives and copied license texts do not automatically satisfy every third-party requirement. Test rebuilding with the required modified library/source delivery and preserve the result as review evidence. See [NOTICE.md](../NOTICE.md) and [third-party boundaries](THIRD_PARTY.md).

The current policy points to a manifest generated by [release-materials.py](../Scripts/release-materials.py). Its reviewed source inventory pins the separate upstream archives. Preparation requires successful replacement tests for two actually compiled LGPL packages using a local module replacement, relinking of the actual Swift application, restored sources and a clean committed production build. The original notices, supplied source inventories and [rebuild instructions](RELINKING.md) accompany the artifacts. CI checks the exact tree and artifact hashes before any binary upload. The checker is a mechanical delivery gate, not an automated legal certification. A different source tree or changed material invalidates the gate.

The exact-tree manifest is generated under ignored build/ after the real deliveries and verification evidence exist. Do not commit a manifest containing its own Git tree hash; that would be self-referential. The producer does not claim a legal opinion, independent security audit or reproducible-byte verification of upstream executables.

The gate stages only hash-verified materials into build/release-materials/. The upload producer then creates an explicit build/release-upload/ directory containing those files, the verified DMG, public reports, build information, release notes and checksums. Filename collisions and files changed during staging are rejected; unrelated workspace/cache files are not copied. ZIP build intermediates are removed; the release installer is a DMG.

## Local and CI behavior

~~~bash
python3 Scripts/check-release-policy.py
python3 Scripts/check-release-policy.py --require-binary
python3 Scripts/check-release-policy.py --configuration-only
~~~

The first two commands validate actual build/source materials; the second also rejects a disabled policy. The third is a configuration check for source-only jobs and cannot authorize upload or emit an enabled output. It does not bypass the full packaging gate.

Matching version tags trigger a separate GitHub Actions release job with write access limited to that job. It verifies the artifact checksums and source commit, creates a draft prerelease, uploads only the verified files, downloads them again and verifies their checksums before publishing. Branch builds produce an Actions artifact without creating a Release. Published releases are not overwritten by reruns. No private signing credentials are required.

Source checks use exact HEAD/index blobs and full Git history. Commit all reviewed documentation, then run:

~~~bash
python3 Scripts/check-documentation.py --source head
python3 Scripts/audit-source.py --source history
~~~

Keep the development-preview label until the separate security, live-funds and notarization acceptance work is complete. Enabling artifact delivery does not establish that the wallet is independently audited or production-ready.
